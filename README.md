# spiral-cube-web-builder (Прототип)

Локальный web-интерфейс, который загружает снимок 4x4 bandaged-куба, запускает поиск на **Node-сервере** (отдельный процесс, полная нагрузка на CPU ПК) через HTTP API и отображает прогресс с пошаговым проигрывателем.

⚠️ Это не финальная версия, не все позиции/кубы могут быть собраны!

## Быстрый старт

1. Установите Node.js 20+.
2. Установите зависимости:
   - `npm install`
3. Запустите **интерфейс и солвер** вместе (рекомендуется):
   - `npm run dev:full` — Vite + API на `http://127.0.0.1:8787`, прокси `/api` из dev-сервера.
4. Либо в двух терминалах: `npm run server`, затем `npm run dev`.
5. Откройте адрес Vite (обычно localhost:5173) в браузере.

## Встроенный снимок

Приложение импортирует `spyral4-assembly.json` из корня проекта как входные данные по умолчанию.
`done.json` - собранный вариант

## Модель куба (важно для совпадения с реальностью)

- **Стикеры**: сетка 4×4 на каждой грани, порядок граней `U D F B R L`, индексы стикеров **0..95** в `bonds` — как в ваших JSON.
- **Повороты**: внешние `U D L R F B`, wide `Uw Dw Lw Rw Fw Bw`, внутренние слои `u d l r f b`, с `'` и `2`. Перестановка стикеров и **ремэп `bonds`** после каждого хода.
- **Бандажи в UI «auto»**: если максимальный индекс в `bonds` ≤ 64 — трактуем пары как **id мини-кубика 0..63** (см. ось ниже); иначе — **пары стикеров**. В настройках солвера можно принудительно выбрать режим.
- **Оси мини-кубиков (id = x + 4y + 16z, x,y,z ∈ 0..3)**: правый слой `R` — `x=3`, `Rw` — `x∈{3,1}`, `r` — `x=1`; левый `L` — `x=0`, `Lw` — `x∈{0,2}`, `l` — `x=2`; верх `U` — `y=3`, и т.д. по аналогии с `moves.ts`.

Если реальный куб крутится иначе (другая нотация wide), сравните с этой схемой и пришлите правку.

## Реализованные модули

- `src/solver/state.ts`: парсинг снимка, валидация, преобразование состояния.
- `src/solver/moves.ts`: механика поворотов граней 4x4 и поиск затрагиваемых индексов.
- `src/solver/bandage.ts`: проверки на легальность бандажей.
- `src/solver/search.ts`: поиск (beam / полный iterative deepening), цель `done.json`, настройки из UI.
- `server/index.ts`: HTTP API (`POST /api/solve`, NDJSON-стрим прогресса).
- `src/solver/runSolveJob.ts`: общая точка входа для сервера (и для `solve:console`).
- `src/ui/CubeView.tsx`: отображение сетки куба.
- `src/ui/SolverPanel.tsx`: панель прогресса и управления проигрывателем.
- `src/solver/search.test.ts`: smoke-тесты для парсера, движений и поиска.
